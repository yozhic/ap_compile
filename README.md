# Compiling complete AkelPad package

Самостоятельная компиляция AkelPad с плагинами из [исходного кода](https://sourceforge.net/p/akelpad/codesvn/HEAD/tree/).  

## Совместимость

- $`\geq`$ [CodeSVN revision 4447](https://sourceforge.net/p/akelpad/codesvn/4447/)  
- наборы для компиляции версий $`\leq`$ r4445 см. в [`_arc_`](./_arc_)  

## Требования

- Microsoft Visual C++ Toolkit 2003. Расположение: `c:\Program Files\`. Скачать: [archive.org](https://archive.org/details/microsoft-visual-c-toolkit-2003), _например_.  
- Windows Server 2003 R2 Platform SDK. Расположение: `c:\Program Files\`. Скачать: [archive.org](https://archive.org/details/platform-sdk-for-microsoft-windows-server-2003-r2-march-2006-edition-english), _например_.  
- Утилиты в папке [`tools`](./akelpad_4/tools). _См. readme.md по ссылке._  

## Запуск

Папку `akelpad_4_build` копируем в любое место, но так, чтобы были права на запись и желательно чтобы путь был без пробелов.  
Содержимое из `akelpad_4` исходников копируем в [`akelpad_4_build\src`](./akelpad_4_build/src) , т.о. конечная структура должна быть следующей:  

```
akelpad_4_build\
  ├─ extras\
  └─ src\
       ├─ AkelAdmin\
       ├─ AkelEdit\
       ├─ AkelFiles\
       ├─ LibraryTest\
       ├─ RegExpTest\
       └─ ...
```

Файл `AkelUpdater.exe` и файлы плагинов от других разработчиков размещаем в [`extras`](./akelpad_4/extras). У каждого набор сторонних плагинов свой (или их нет совсем), поэтому проверка состава этой папки не предусмотрена (только наличие).  

Для компиляции обычной версии запускаем [`build.cmd`](./akelpad_4/build.cmd)  
Для компиляции отладочной версии запускаем [`build_debug.cmd`](./akelpad_4/build_debug.cmd)  

## Настройки

Ключ запуска — для файлов `build.cmd` и `build_debug.cmd`. Значение указываем после двоеточия.  
IA = _интерактивность_ — возможность редактировать настройку после запуска в окне консоли, ориентируясь на подсказки.  
B = `build.cmd`  
BD = `build_debug.cmd`  

| Настройка | Ключ запуска | IA | B | BD | Описание |
|:--------- |:------------:|:--:|:-:|:--:|:-------- |
| Номер редакции | `/rv:r4547` | ✅ | ✅ | ✅ | Номер последней правки на [CodeSVN](https://sourceforge.net/p/akelpad/codesvn/HEAD/tree/). `r` = _revision_. |
| Дата редакции | `/dt:26.08.2026` | ✅ | ✅ | ✅ | Дата последней правки на CodeSVN. Формат любой. |
| Сведения о сборке | `/cm:1` | ✅ | ✅ | 🚫 | 1. В окно About добавляется запись о номере и дате редакции.<br>2. В свойства .dll добавляются записи о номере и дате редакции.<br><br>`1` = добавить<br>`0` = не добавлять<br><br>В отладочной версии настройка недоступна: сведения добавляются автоматически. |
| Дополнительная Toolbar | `/tx:0` | ✅ | ✅ | 🚫 | Создаётся дубликат плагина Toolbar.dll, из которого удаляются иконки (не нужны, при необходимости используются из стандартного Toolbar.dll). Этот облегчённый дубликат можно использовать для создания дополнительных панелей инструментов.<br><br>`1` = создавать<br>`0` = не создавать<br><br>В отладочной версии настройка недоступна: дубликат не создаётся.  |
| Другие дополнения | `/ex:0` | ✅ | ✅ | 🚫 | 1. Добавляется цветовая тема One Dark Pro (от [Rinat'а](https://akelpad.sourceforge.net/forum/viewtopic.php?p=36161#p36161)).<br><br>`1` = добавить<br>`0` = не добавлять<br><br>В отладочной версии настройка недоступна: тема не добавляется. |
| Режим отладки скрипта | `/db:0` | ✅ | ✅ | 🚫 | В этом режиме выполнение сценария периодически останавливается на паузу (для «отлова» сбоев).<br><br>`1` = включить<br>`0` = не включать<br><br>В отладочной версии настройка недоступна: «отлавливаем» сбои в обычной. |
| Подсказки | `/hs:1` | 🚫 | ✅ | ✅ | В этом режиме в окне консоли выводятся подробные подсказки по настройкам. Когда привыкнешь, можно отключать — меньше болтовни.<br><br>`1` = включить<br>`0` = не включать<br><br>Настройка доступна только в виде ключа при запуске. |

При каждом запуске сценариев настройки, выбранные в окне консоли, сохраняются в файле `arguments.cfg`. Чтобы не сохранять, добавляем дефис/минус `-` в строку запроса (например, `+ -` означает — редактировать всё, но не сохранять выбор в файл).

Перед следующим запуском сценария можно отредактировать настройки в `arguments.cfg`, чтобы не заниматься этим в окне консоли.

У настройки, переданной в ключе при запуске сценария, приоритет выше, чем у такой же настройки в `arguments.cfg`.

В сценарии для сборки отладочной версии `build_debug.cmd` учитываются только настройки `/rv`, `/dt` и `/hs` — остальные там просто неуместны.
